# Лабораторная работа №2: Трекинг объекта на видео на основе ключевых точек

## Цель работы
Реализовать алгоритм трекинга плоского прямоугольного объекта на видео с использованием методов компьютерного зрения, основанных на детектировании и сопоставлении ключевых точек.

---

## 1. Теоретическая база

Система опирается на данные методы компьютерного зрения:

* **SIFT (Scale-Invariant Feature Transform)**: Алгоритм выделения и описания локальных особенностей. Инвариантен к масштабу, повороту и частично к изменению освещённости. Для каждой точки строится 128-мерный градиентный дескриптор. Используется как «якорь» для глобальной коррекции позиции объекта.
* **Оптический поток Лукаса-Канаде (Lucas-Kanade)**: Итеративный метод отслеживания перемещения характерных точек между соседними кадрами, основанный на предположении о постоянстве яркости и малости перемещения. Для повышения надёжности применяется **двусторонняя проверка (forward-backward error)**: точка считается корректно отслеженной, если при трекинге «вперёд-назад» она возвращается в исходную позицию с ошибкой ниже порога.
* **Гомография и USAC-MAGSAC**: Положение плоского объекта описывается матрицей гомографии $3 \times 3$. Для её устойчивой оценки в условиях наличия выбросов (outliers) используется алгоритм **USAC-MAGSAC** (Modern Adaptive Consensus), который превосходит классический RANSAC по скорости и точности подбора модели, минимизируя влияние шумных сопоставлений.

**Почему гибридный подход?** 
Использование только SIFT на каждом кадре слишком ресурсоёмко. Использование только LK приводит к накоплению ошибки (дрейфу) и потере объекта при быстром движении или окклюзии. Гибридная система использует LK для плавного и быстрого межкадевого трекинга, а SIFT периодически «подтягивает» позицию, сбрасывая накопленный дрейф.

## 2. Архитектура и пайплайн системы

Код модульно организован внутри пакета `source` с чётким разделением ответственности:
* `main.py`: Управление основным циклом обработки и конечным автоматом (state machine) трекинга.
* `matching.py`: Построение пирамиды шаблонов, детекция SIFT в ROI и полнокадровый поиск.
* `lk.py`: Инициализация и трекинг оптическим потоком.
* `geometry.py`: Многоступенчатая геометрическая валидация гипотез.
* `drawing.py` и `video_io.py`: Визуализация и работа с файлами.

### 2.1 Конвейер обработки кадра:
1. **Инициализация**: Из первого кадра извлекаются ключевые точки SIFT. Строится **пирамида шаблонов** (набор уменьшенных копий от 1.0 до 0.09) для устойчивого поиска объекта на разных расстояниях от камеры. Выбираются до 150 лучших точек для LK-трекинга.
2. **Фаза 1: Быстрый трекинг (LK)**: На каждом кадре алгоритм проецирует референсные точки LK в текущий кадр с помощью текущей гомографии и отслеживает их. Если геометрические проверки проходят успешно, объект считается найденным.
3. **Фаза 2: Адаптивный троттлинг SIFT**: Полноценный SIFT запускается не каждый кадр, а по условию:
   - *Если LK дал сбой*: немедленный запуск SIFT в ROI (области интереса).
   - *Если LK успешен*: запуск SIFT происходит с интервалом, зависящим от размера объекта (для мелких объектов проверка чаще, для крупных – реже), чтобы предотвратить дрейф.
4. **Фаза 3: Поиск SIFT**:
   - Сначала выполняется поиск в **ROI** (масштабируемой области вокруг последней известной позиции).
   - Если объект потерян (`lost > 0`) и истёк период `cooldown`, выполняется **полнокадровый поиск** (full-frame) с пониженным разрешением для ускорения.
5. **Фаза 4: Подтверждение и обновление**: При повторном обнаружении после потери система требует геометрического совпадения в течение нескольких кадров (`CONFIRM_FRAMES`), чтобы избежать ложных срабатываний на фоне. При успешном подтверждении точки LK **перевыбираются заново** на основе актуальной позиции SIFT, что полностью сбрасывает накопленный дрейф.

### 2.2 Геометрическая валидация гипотез

Каждая гипотеза положения объекта (рамка) проходит строгую многоступенчатую проверку, что предотвращает «улетание» трекинга на текстурированный фон:

| Проверка | Описание | Цель |
| :--- | :--- | :--- |
| `valid_box` | Объект должен находиться в пределах границ кадра и иметь площадь выше минимального порога. | Отсечение артефактов на краях кадра. |
| `reasonable_quad` | Четырёхугольник рамки должен быть строго выпуклым, а внутренние углы находиться в диапазоне 30°–150°. | Исключение вырожденных перспективных искажений. |
| `plausible_aspect` | Соотношение сторон не должно критически отличаться от эталонного (с допуском на перспективу). | Защита от сопоставления с объектами другой формы. |
| `side_lengths_consistent` | Длины противоположных сторон должны быть соизмеримы. | Дополнительная проверка корректности перспективы. |
| `inliers_cover_quad` | Внутренние точки (inliers), использованные для расчёта гомографии, должны покрывать значительную часть площади рамки. | Гарантия того, что гомография построена на реальных признаках объекта, а не на случайном шуме. |
| `boxes_consistent` | Положение и размер рамки не должны меняться слишком резко между соседними кадрами. | Сглаживание трекинга и отсев внезапных ложных скачков. |

## 3. Результаты работы и тестирования системы

Алгоритм был протестирован на предоставленных тестовых видео, а также на собственном видео, снятом на камеру смартфона.

| Тестовый сценарий | Качество трекинга | Примечание |
| :--- | :--- | :--- |
| **Плавное движение и поворот** | Хорошее | Рамка точно следует за границами объекта. LK-трекинг обеспечивает стабильность без мерцания. |
| **Изменение масштаба (удаление/приближение)** | Хорошее | Пирамида шаблонов и адаптивный ROI позволяют успешно находить объект даже при значительном уменьшении его размера в кадре (до ~10% от исходного). |
| **Размытие в движении (Motion Blur)** | Удовлетворительное | При сильном размытии LK может давать сбой, но система быстро переключается на SIFT и восстанавливает положение объекта. |

## 4. Выводы по работе

В ходе выполнения лабораторной работы был реализован и исследован гибридный алгоритм трекинга плоского объекта.

**Достигнутые результаты:**
1. Комбинация SIFT и Lucas-Kanade позволила достичь оптимального баланса: SIFT корректирует накопленную ошибку дрейфа (drift), а LK обеспечивает плавный и быстрый трекинг между кадрами.
2. Внедрение пирамиды шаблонов и адаптивного масштабирования ROI решило проблему потери объекта при изменении расстояния до камеры.
3. Многоступенчатая геометрическая валидация эффективно отсеивает ложные срабатывания на текстурированных фонах, делая систему надёжной.

**Ограничения:**
* Алгоритм требует наличия выраженной текстуры на объекте. На однородных поверхностях (например, белый лист бумаги) количество ключевых точек недостаточно для надёжной оценки гомографии.
* При экстремально быстром движении камеры возможны кратковременные потери объекта, требующие полного перебора кадра (full-frame search), что снижает FPS.

**Возможные направления улучшения:**
* Замена SIFT на более быстрые бинарные дескрипторы (ORB, AKAZE) для повышения производительности на слабых устройствах.
* Добавление фильтра Калмана для предсказания положения рамки в случаях полной окклюзии.
