# Лабораторная работа №2: Трекинг объекта на видео на основе ключевых точек

## Цель работы
Реализовать алгоритм трекинга плоского прямоугольного объекта на видео с использованием методов компьютерного зрения, основанных на детектировании и сопоставлении ключевых точек.

---

## 1. Теоретическая база

Для решения задачи трекинга в работе используется гибридный подход, сочетающий скорость оптического потока и надёжность инвариантных дескрипторов.

* **SIFT (Scale-Invariant Feature Transform)** – алгоритм детектирования и описания локальных особенностей изображения. Он инвариантен к изменению масштаба, повороту и частично к изменению освещённости. Для каждой ключевой точки строится 128-мерный вектор-дескриптор на основе градиентов в её окрестности.
* **FLANN (Fast Library for Approximate Nearest Neighbors)** – библиотека для быстрого приближённого поиска ближайших соседей в многомерных пространствах. Используется для эффективного сопоставления SIFT-дескрипторов между кадрами. Для отсеивания ложных совпадений применяется **тест Лоу (Lowe's ratio test)**: отношение расстояния до ближайшего соседа ко второму ближайшему должно быть меньше заданного порога (по умолчанию 0.78).
* **Оптический поток Лукаса-Канаде (Lucas-Kanade)** – метод отслеживания перемещения характерных точек между соседними кадрами. Основан на предположении о постоянстве яркости точки и малости её перемещения. Для повышения надёжности используется **двусторонняя проверка (forward-backward error)**: точка считается корректно отслеженной, если при трекинге туда и обратно она возвращается в исходную позицию с ошибкой менее заданного порога.
* **Гомография и USAC_MAGSAC** – положение плоского объекта описывается матрицей гомографии $3 \times 3$. Для её устойчивой оценки в условиях наличия выбросов (outliers, т.е. неправильно сопоставленных точек) используется алгоритм **USAC_MAGSAC** (улучшенная версия RANSAC), который максимально точно определяет геометрическое преобразование, минимизируя влияние шума.

## 2. Описание разработанной системы

### 2.1. Архитектура
Система реализована на языке Python с использованием библиотеки OpenCV. Код структурирован модульно внутри одного файла с чётким разделением ответственности функций:
* `build_ref_pyramid`, `detect_in_roi`, `detect_full_frame` – поиск и сопоставление признаков.
* `track_flow` – трекинг оптическим потоком.
* `reasonable_quad`, `plausible_aspect`, `boxes_consistent` и др. – геометрическая валидация гипотез.
* `draw_keypoints` – визуализация результатов.

### 2.2. Принцип работы (Гибридный алгоритм)
Алгоритм работает в конвейере, выбирая наиболее эффективный метод для текущего состояния:

1. **Инициализация**: из первого кадра (или загруженного шаблона) извлекаются ключевые точки SIFT. Строится **пирамида шаблонов** – набор уменьшенных копий шаблона (от 1.0 до 0.09) для устойчивого поиска объекта на разных расстояниях от камеры.
2. **Быстрый трекинг (LK)**: на каждом кадре алгоритм пытается отслеживать до 150 наиболее надёжных ключевых точек с помощью оптического потока. Если геометрические проверки проходят успешно, объект считается найденным. Это обеспечивает высокую производительность (высокий FPS) и плавность рамки.
3. **Локальный поиск (SIFT in ROI)**: если LK-трекинг не удаётся или прошло заданное количество кадров, выполняется поиск SIFT-признаков в расширенной области интереса (ROI) вокруг последнего известного положения объекта. ROI адаптивно масштабируется (upscaling/downscaling), чтобы обеспечить оптимальное количество точек для детектора.
4. **Глобальный поиск (Full-frame)**: если объект потерян (не найден в ROI), алгоритм периодически выполняет поиск по всему кадру с понижением разрешения для ускорения. После обнаружения требуется подтверждение (`CONFIRM_FRAMES`) в нескольких последовательных кадрах для защиты от ложных срабатываний на фоне.

### 2.3. Геометрическая валидация
Каждая гипотеза положения объекта проходит строгую многоступенчатую проверку, что предотвращает "улетание" рамки на фон:
* `valid_box`: объект должен находиться в пределах кадра и иметь разумную минимальную площадь.
* `reasonable_quad`: четырёхугольник рамки должен быть выпуклым, а его углы не должны быть экстремально острыми или тупыми (между 30° и 150°).
* `plausible_aspect` и `side_lengths_consistent`: соотношение сторон и длины противоположных сторон не должны критически отличаться от шаблона (с допуском на перспективу).
* `inliers_cover_quad`: внутренние точки (inliers), использованные для расчёта гомографии, должны покрывать значительную часть площади рамки.
* `boxes_consistent`: положение и размер рамки не должны меняться слишком резко между соседними кадрами.

## 3. Результаты работы и тестирования системы

Алгоритм был протестирован на предоставленных тестовых видео, а также на собственном видео, снятом на камеру смартфона.

| Тестовый сценарий | Качество трекинга | Примечание |
| :--- | :--- | :--- |
| **Плавное движение и поворот** | Хорошее | Рамка точно следует за границами объекта. LK-трекинг обеспечивает стабильность без мерцания. |
| **Изменение масштаба (удаление/приближение)** | Хорошее | Пирамида шаблонов и адаптивный ROI позволяют успешно находить объект даже при значительном уменьшении его размера в кадре (до ~10% от исходного). |
| **Размытие в движении (Motion Blur)** | Удовлетворительное | При сильном размытии LK может давать сбой, но система быстро переключается на SIFT и восстанавливает положение объекта. |

## 4. Выводы по работе

В ходе выполнения лабораторной работы был реализован и исследован гибридный алгоритм трекинга плоского объекта.

**Достигнутые результаты:**
1. Комбинация SIFT и Lucas-Kanade позволила достичь оптимального баланса: SIFT корректирует накопленную ошибку дрейфа (drift), а LK обеспечивает плавный и быстрый трекинг между кадрами.
2. Внедрение пирамиды шаблонов и адаптивного масштабирования ROI решило проблему потери объекта при изменении расстояния до камеры.
3. Многоступенчатая геометрическая валидация эффективно отсеивает ложные срабатывания на текстурированных фонах, делая систему надёжной.

**Ограничения:**
* Алгоритм требует наличия выраженной текстуры на объекте. На однородных поверхностях (например, белый лист бумаги) количество ключевых точек недостаточно для надёжной оценки гомографии.
* При экстремально быстром движении камеры возможны кратковременные потери объекта, требующие полного перебора кадра (full-frame search), что снижает FPS.

**Возможные направления улучшения:**
* Замена SIFT на более быстрые бинарные дескрипторы (ORB, AKAZE) для повышения производительности на слабых устройствах.
* Добавление фильтра Калмана для предсказания положения рамки в случаях полной окклюзии.

## Приложение: Инструкция по запуску

### Требования
* Python 3.8+
* OpenCV 4.x (`pip install opencv-python`)
* NumPy (`pip install numpy`)

### Запуск программы
```bash
# Базовый запуск (объект берётся из первого кадра)
python main.py test-videos/mona-lisa-blur-extra-credit.avi

# С ручным выделением области объекта на первом кадре
python main.py test-videos/mona-lisa-blur-extra-credit.avi --roi

# Использование внешнего изображения в качестве шаблона
python main.py test-videos/video.mp4 --template template.jpg
```

### Доступные аргументы командной строки
| Аргумент | Описание |
| :--- | :--- |
| `--template` | Путь к изображению шаблона (по умолчанию: первый кадр видео) |
| `--roi` | Позволяет выделить объект мышкой на старте |
| `--min-matches` | Минимальное количество совпадений точек (по умолчанию: 8) |
| `--ratio` | Порог теста Лоу для сопоставления (по умолчанию: 0.78) |
| `--no-lk` | Отключить оптический поток, использовать только SIFT |
| `--no-show-kp` | Скрыть отрисовку ключевых точек для чистоты изображения |
| `--no-throttle` | Отключить ограничение FPS (воспроизведение на максимальной скорости) |
